## 播放器脚本与辅助请求实验

继续使用同一真实视频、已安装增强引擎和现有代理，在独立临时目录匿名测试，不改动安装版参数。以下是探索性小样本，不能直接外推到 Chrome 登录、其他视频或所有网络环境。

### 跳过辅助请求

按默认、候选、候选、默认、默认、候选交替，候选为 `player_skip=configs,initial_data`。

- 默认：6.034 / 3.098 / 3.056 秒，中位数 3.098 秒。
- 候选：3.084 / 3.058 / 3.081 秒，中位数 3.081 秒。
- 六轮均有网页、播放器脚本和 JS 验证阶段；最高 2160p。没有证据表明当前流程实际减少了关键请求，因此不采用该参数。

### 按完整播放器 URL 缓存公开脚本

临时 yt-dlp 提取器插件覆写 `_load_player`，以完整播放器 URL 的 SHA-256 为键存储脚本文本，命中后仍正常执行 JS 验证。初次试验插件目录未正确加载，其结果不作为缓存证据。修正后日志明确记录缓存保存、加载和命中：

| 路径 | 时间（秒） | 说明 |
| --- | --- | --- |
| 默认首轮 | 5.505 | 独立服务启动后的首次网络请求 |
| 缓存首次 | 3.118 | 尚无脚本缓存，下载并保存 |
| 缓存命中 | 2.416 | 无播放器脚本下载，验证仍执行 |
| 默认预热 | 3.169 | 播放器脚本下载约 0.611 秒 |
| 默认预热 | 3.385 | 播放器脚本下载约 0.553 秒 |
| 缓存命中 | 2.735 | 无播放器脚本下载，验证仍执行 |

两次预热默认平均 3.277 秒，两次命中平均 2.576 秒，约少 0.70 秒（21%）；样本很小，直接可确认的收益是省去约 0.6 秒的一次脚本网络下载。

各轮最高 2160p，标题、时长、频道和描述未观察到差异。格式数量在 120 / 122 间波动，默认轮次也出现；章节及自动字幕字段在不同请求间变化，因此尚不能声称元数据完全等价。

另起一次独立验证：命中脚本缓存的解析仍耗时 5.151 秒，其中等待到网页处理之后的缓存加载为 4.572 秒，说明脚本缓存无法消除网页请求的冷启动或网络波动。随后复用解析结果实际请求 2160p SABR 媒体，1.149 秒收到首个正数 downloaded_bytes，没有 URL 回退；随即停止，未下载完整视频。

结论：辅助请求跳过无明显收益；公开播放器脚本缓存有可测收益，但目前仅为临时实验，未接入生产应用。正式接入前需补充缓存大小与有效期限制、损坏处理、脚本失效后的重新下载回退，以及登录场景和多视频验证。不会复用或跳过每个媒体会话所需的 JS 验证结果。

### 校验通过但脚本不可用

人为写入无效 JavaScript，同时更新其 SHA-256，使文件完整性检查通过。原型最初解析失败（退出码 1）；只捕获提取异常仍不能恢复，因为引擎可能返回不含有效媒体格式的结果，随后才在格式选择阶段报错。

临时原型增加“命中脚本缓存后异常或没有有效媒体格式”的检查，清除使用过的缓存与进程内脚本缓存，并绕过磁盘缓存完整重试一次。真实视频验证在 4.760 秒触发回退，重新请求网页与播放器后，7.059 秒成功结束，恢复 2160p、38 个格式。该异常路径允许比正常流程更慢，重点是自动恢复；不重复循环重试。

该测试支持继续开发正式实现，但尚未覆盖只丢失部分格式而仍返回可下载媒体、所有动态范围、所有登录限制视频或并发缓存竞争，不能将其当作完整发布验证。
