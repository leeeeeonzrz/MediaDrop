# 播放器脚本缓存的安全边界

正式实现使用后端进程内的 RAM 缓存，替代之前的临时磁盘实验。应用重启即清空；首次解析仍需下载脚本。既有任务元数据缓存与此缓存相互独立。

## 数据和来源

- 仅缓存公开播放器脚本文本，不缓存 Cookie、PO Token、每个视频的 JS 验证结果或媒体地址。
- 来源限制为 `https://www.youtube.com/s/player/<十六进制版本>/… .js`，拒绝端口、用户信息、查询串、片段、路径穿越、百分号编码和控制字符。
- 请求完成后的最终 URL 必须与原 URL 完全相同且符合上述规则，才能写入缓存。重定向到其他地址的响应不会写入缓存。底层提取器原有网络行为不被改变。
- TLS 验证仍由下载引擎负责；若调用方关闭证书验证，则不使用该缓存。
- 不使用“脚本与校验值一起保存在文件里”的信任模型。磁盘文件、符号链接和磁盘缓存替换不参与这条缓存路径。

## 进程间访问

- 缓存服务位于应用现有的 `127.0.0.1` HTTP 服务，仅启用在明确绑定回环地址的桌面后端。
- 每次后端启动生成独立的 256 位随机凭证，通过子进程环境交给下载引擎，不放进 URL、命令行、前端或浏览器 Cookie。
- 每次请求检查凭证（常量时间比较）、来源地址、精确 Host，拒绝所有带 Origin 的浏览器请求。不提供 CORS 授权。
- 插件仅访问固定的回环路径；内部 HTTP 客户端禁用代理和重定向，防止把凭证发送到其他服务器。请求、响应、超时均有上限；服务不可用时直接重新获取脚本。
- 增强引擎忽略外部配置，并禁用默认插件目录，只加载随应用打包的插件。

## 生命周期和回退

- 按引擎版本与完整播放器 URL 隔离，单脚本最多 8 MiB、总文本预算 32 MiB、最多 16 项，有效期 24 小时。实际进程峰值还包含 JSON、请求体等短期副本，不等于 32 MiB。
- 缓存操作加锁；容量回收与访问顺序一致，不依赖缓存文件锁或原子文件写入。
- 命中缓存后遇到提取异常、已知签名/JS 验证失败警告，或没有有效媒体格式时，失效相关缓存，清除提取器进程内脚本缓存，并绕过共享缓存重新提取一次。第二次失败正常报告，不无限重试。
- 不跳过 JS 验证，也不扩大原有 JS 运行环境的权限。未识别的静默部分格式丢失不能保证全部被检测，应持续跟进引擎变化。

## 威胁模型与限制

防护对象包括普通网站跨站访问、无凭证的本地请求、错误来源缓存、磁盘缓存替换、超大缓存输入、过期与不兼容脚本。它不把同一用户权限下的恶意进程或已被控制的下载引擎视为强隔离边界：此类进程可能读取其他进程环境或内存。也不消除上游官方脚本、TLS 信任链、下载引擎或 JS 运行时自身的风险。

## 验证

- 134 项后端测试及前端、桌面回归检查通过，新增来源策略、独立凭证、Host/Origin/远程地址拒绝、请求上限、TTL、容量、并发、重定向禁止、代理禁用、异常及部分格式警告回退覆盖。
- 正式代码对两个真实 2160p 视频完成缓存命中与默认流程对照，格式数分别保持 120 / 38。
- 在隔离测试服务中注入不可用脚本后，确认一次自动回退恢复 2160p、38 个格式，并收到实际媒体数据。
- 最终签名安装版通过 Chrome Cookie 实际解析并命中内存缓存（3.290 秒），同时确认拒绝无凭证的外站 Origin 请求（403）。
- 这些是功能和安全回归测试，不是第三方安全审计，也不代表所有站点变体、HDR 或未来引擎版本均已覆盖。
